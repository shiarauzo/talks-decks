Sin reglas, el movimiento se decide a ojo.

Taste en motion es un sistema entrenable: propósito, frecuencia, duración y curva.

Citar animations.dev: hoy salimos con un blueprint — propósito, frecuencia, duración y curva.

Una microinteracción es un momento con un solo trabajo.

Ejemplos: like, toggle, toast, press, pull-to-refresh, validación de un campo.

  • 1Trigger — qué la inicia (click, hover, scroll, timer)
  • 2Rules — qué pasa si / si no
  • 3Feedback — qué ve o siente el usuario
  • 4Loops / modes — se repite, cambia, o termina
Modelo clásico de Dan Saffer, útil para no confundir microinteracción con “animación decorativa de marketing”.

02

Buenas y malas interacciones

Misma intención. Distinto craft. La diferencia se siente antes de explicarse.

Pedir silencio 2 segundos en cada demo. Que el público vote con la mano: izquierda o derecha se siente mejor.

Press: ¿la UI escuchó?

Sin feedback táctil

Mala

Solo estado default. Sin :active.

Scale en :active

Buena

:active { transform: scale(0.97) } · 150ms ease-out

Haz que todos clickeen mentalmente. La de la derecha confirma el press. La izquierda se siente muerta o perezosa.

Misma duración. Distinta sensación.

ease-in, 300ms

Se siente lenta

Empieza lento. El usuario espera.

ease-out, 180ms

Se siente snappy

Empieza rápido. Responde al click.

Abrir ambos. Insistir: la duración real no importa tanto como el primer frame de movimiento. Nunca uses ease-in para UI iniciada por el usuario.

Duración cambia la percepción de velocidad.

Spinner lento

App “pesada”

Mismo “tiempo de carga”. Peor percepción.

Spinner rápido

App “ágil”

No acorta la red. Sí cambia cómo se siente.

Perceived performance. Un select a 180ms se siente más responsivo que uno a 400ms aunque ambos “funcionen”.

03

Basics de movimiento

Duration, easing, curves, bezier, transform. Las cinco palancas que controlan el feel.

Pasar de “se ve raro” a vocabulario preciso. Si no puedes nombrarlo, no puedes arreglarlo.

Duration: cuánto tiempo se mueve.

Regla práctica: UI bajo 300ms. Si duda, acorta.

Elemento Rango
Press de botón 100–160ms
Tooltip / popover chico 125–200ms
Dropdown / select 150–250ms
Modal / drawer 200–500ms
Marketing / explicación Puede ser más largo
Mostrar la tabla como defaults, no como dogma. El mood del producto mueve el rango (Sonner es un poco más lento a propósito). Regla práctica: UI bajo 300ms.

Cómo se reparte ese tiempo.

  • 1 Duration — cuánto dura el movimiento
  • 2 Easing — si acelera, frena o va constante
  • 3 linear — velocidad constante
  • 4 ease-in — empieza lento, acelera
  • 5 ease-out — empieza rápido, frena
  • 6 ease-in-out — suave al inicio y al final
Vocabulario mínimo. Luego una curva por slide.

linear

Usar

  • Spinners y loaders
  • Progress bars
  • Marquee / loops constantes

No usar

  • Modales y drawers
  • Dropdowns y toasts
  • Cualquier enter / exit de UI
Velocidad fija. En UI se siente mecánico; en loops se siente honesto.

ease-in

Empieza lento y termina rápido. En producto casi nunca.

Usar

  • Caída / gravedad (item a la papelera)
  • Algo que se “escapa” de pantalla
  • Marketing o game feel con impacto al final

No usar

  • Opens (modal, menu, toast)
  • Press / hover / click
  • Enter o exit de UI de producto
El usuario mira el primer frame. Si arranca lento, la app se siente lenta aunque dure lo mismo. Para UI: ease-out. ease-in queda para metáforas físicas (caer, escapar), no para controles.

ease-out

Usar

  • Enter de UI (default)
  • Dropdowns, popovers, toasts
  • Press y feedback al click

No usar

  • Spinners / progress loops
  • Marquee continuo
  • Movimiento que no debe frenar
La curva que más van a usar. Enter / exit → ease-out.

ease-in-out

Usar

  • Morphs de algo ya visible
  • Mover un elemento en pantalla
  • Transiciones de layout grandes

No usar

  • Opens / closes de UI
  • Dropdowns y modales
  • Respuesta rápida a un click
Para transformar lo que ya se ve. No para opens.

El blueprint de easing.

  • →¿Entra o sale? → ease-out
  • →¿Se mueve / morph en pantalla? → ease-in-out
  • →¿Hover / color? → ease
  • →¿Movimiento constante? → linear
  • →Default → ease-out
Sistema de Emil. Repetirlo en voz alta. Luego: las curvas built-in de CSS son débiles; usa custom.

Bezier: la curva custom.

cubic-bezier(x1, y1, x2, y2) define dos handles. No inventes curvas: copia de easing.dev y guárdalas como tokens CSS.

ease-out: 0.23, 1, 0.32, 1 ease-in-out: 0.77, 0, 0.175, 1 drawer: 0.32, 0.72, 0, 1

--ease-out: cubic-bezier(0.23, 1, 0.32, 1);

Si hay tiempo, abrir easing.dev en una ventana. Si no, dejar el recurso para después.

Transform: qué propiedades mover.

Usa Evita animar
transform (translate, scale, rotate) width / height
opacity top / left
clip-path (con cuidado) margin / padding
filter sutil (blur ≤ 2–4px) transition: all
Solo transform y opacity van a compositor/GPU de forma predecible. El resto dispara layout y paint.

Detalles de transform que importan.

  • 1 translateY(100%) es relativo al propio elemento. Ideal para drawers y toasts.
  • 2 scale() escala también a los hijos. El texto “respira” con el botón.
  • 3 transform-origin define desde dónde crece. Popovers: desde el trigger. Modales: centro.
Origin-aware es uno de esos detalles “invisibles” que en agregado hacen que el producto se sienta caro.

Origin-aware vs centro.

04

Patrones útiles

No son librerías. Son decisiones reutilizables.

Patrón: press feedback

Aplica a cualquier cosa presionable. Rango seguro: 0.95–0.98. 

.button {
  transition: transform 160ms var(--ease-out);
}
.button:active {
  transform: scale(0.97);
}
Este es el patrón más barato con más ROI. Si solo implementan uno hoy, que sea este.

Patrón: stagger de entrada

Cascada 50ms

Delays cortos: 30–80ms. No bloquees interacción.

Reglas

  • –Parte el contenido en chunks semánticos
  • –No animes un solo contenedor gigante
  • –Exit más sutil que enter
Replay un par de veces. Si el delay es largo, la UI se siente lenta aunque cada item sea rápido.
